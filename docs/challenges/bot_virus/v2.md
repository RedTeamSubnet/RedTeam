# Bot Virus v2

## Objective

Build a containerized browser bot that completes the challenge web page
without being flagged by the bot checks. The score comes from the platform's
evaluation of your submitted image.

## What changed from v1

- v1 submissions are not compatible with v2. Do not reuse them.
- The v1 package rule still applies: OS packages only, from the base image's
  default, unmodified sources. v2 narrows it to `apt-get` / `apt`. Language
  package managers and other fetch methods are not allowed. See
  [Dockerfile sources](#dockerfile-sources).
- Build-source and bot-behaviour rules are now stated as numbered checks.
  Validation feedback uses fixed titles (see [Validation feedback](#validation-feedback)).

## Evaluation flow

1. Write `src/commit/bot.py` and `src/commit/Dockerfile` (see
   [Submission contract](#submission-contract)).
2. Verify locally with the miner commit example (see the
   [testing manual](testing_manuals.md)).
3. Build and publish the image, then submit it following the
   [build and publish workflow](../../miner/workflow/3.build-and-publish.md).
4. The submission passes validation. A failed validation sets the status to
   `Invalid` and stops scoring.
5. The platform evaluates the image and reports a score between `0.0` and
   `1.0`, with feedback.

A failed build, a failed run, or a missing result scores `0.0`.

The evaluation infrastructure is private. Miners cannot run it locally.

## Submission contract

`src/commit/` must contain exactly two files:

| File | Requirement |
| --- | --- |
| `bot.py` | At most **2,000** lines. Must pass Ruff. Must define `run_bot(url: str) -> bool`. |
| `Dockerfile` | At most **500** lines. Defines the image the platform builds. |

Use these exact names. Missing, renamed, duplicated, or extra files are rejected.
Subdirectories (such as `__pycache__/`) count as extra files.

### Entry point

`run_bot(url: str) -> bool` receives the challenge page URL, performs the
required page actions, and returns `True` on success or `False` on failure.
Close every browser, driver, and spawned process on every exit path, including
failure.

### Required page actions

The bot must perform these actions, in this order, using these ids exactly:

1. Click `click-here-1`, `click-here-2`, and `click-here-3`. All three corners
   must be clicked before the first keystroke in either field.
2. Type at least **16** characters into `username` (`<input type="text">`) and
   at least **16** characters into `password` (`<input type="password">`).
3. Click `submit`.
4. Wait for the real submission result. Do not declare success on the bot's own.

Run the practice page to confirm your bot meets every requirement; each one
shows PASS or FAIL. The practice page is in the miner commit example
(`examples/miner_commit/practice/index.html`).

### Bot behaviour rules

- **Plainly written.** All logic is visible in `bot.py`. Obfuscated or encoded
  code, `eval`/`exec` of dynamic strings, and hidden payloads are not allowed.
- **Unrelated logic and persistence** are not allowed. `bot.py` may launch only
  the browser and its display server.
- **Network.** `bot.py` contacts only the assigned URL. It must not fetch code,
  dependencies, or data at runtime, send data elsewhere, or install packages at
  runtime.
- **No weakened security, no faked results.** `bot.py` must not disable the
  browser sandbox, request privileged execution, alter host or container
  configuration, spoof or override browser APIs or page globals, or declare
  success on its own.
- **Bounded waits.** Every wait has a timeout. Navigation errors and missing
  elements fail cleanly.

### Ruff

`bot.py` must pass Ruff with the example's `.ruff.toml`:

```sh
ruff check --config .ruff.toml bot.py
```

### Dockerfile rules

- **Base image (`FROM`).** Must be a recognizable official image (for example
  `python`, `debian`, `ubuntu`, `selenium`) or a challenge-maintained base.
  Images from a personal account, an unknown organization, a private registry,
  or an arbitrary repository are rejected. Multi-stage builds are rejected.
- **OS packages.** Only `apt-get` or `apt`, from the base image's default,
  unmodified package sources. Allowed purposes: a headless browser and its
  binaries, a virtual display (xvfb, xdotool), fonts, and ordinary system
  dependencies. Cleanup such as `rm -rf /var/lib/apt/lists/*` is fine. Added
  repositories, PPAs, keys, or signing configuration are rejected, and so are
  unrelated packages (compilers, development toolchains, network utilities not
  needed for browser automation).
- **No direct fetches.** No `curl`, `wget`, `git`, or any other download of a
  URL, archive, script, or repository, including inside `RUN`.
- **No hidden sources.** No remote `ADD`, no `COPY --from`, no multi-stage
  builds, no pipe-to-shell, no `eval`, no decoding of encoded payloads, and no
  archive download-and-extract. An ordinary `COPY` of `bot.py` is allowed.
- **Equivalent layouts are fine.** Harmless differences in paths, ordering, and
  declarative fields are allowed. Any difference that could introduce hidden
  code or dependencies is rejected.
- **Entry point.** `CMD` or `ENTRYPOINT` must start `bot_runner.py` (provided by
  the platform) or `bot.py`.

### Dockerfile sources

Fetch content only from these providers. Any other source fails the build.

| Category | Allowed provider |
| --- | --- |
| Base image (`FROM`) | Base images the challenge makes available |
| Debian packages (`apt-get`) | `*.debian.org` |
| Ubuntu packages (`apt-get`) | `*.ubuntu.com` |
| Alpine packages (`apk`) | `dl-cdn.alpinelinux.org` |
| Python packages (`pip`) | `pypi.org`, `*.pythonhosted.org` |
| JavaScript packages (`npm`, `yarn`) | `*.npmjs.org`, `*.yarnpkg.com` |
| Java packages (Maven) | `repo.maven.apache.org`, `repo1.maven.org` |
| Go modules (`go`) | `proxy.golang.org`, `sum.golang.org` |
| Rust crates (`cargo`) | `*.crates.io` |

Build for `linux/amd64`:

```sh
DOCKER_BUILDKIT=1 docker build --platform linux/amd64 -t <image>:<tag> .
```

## Integration

### Local `/solve` check

The miner commit example's FastAPI service reads every entry in `src/commit/`
and returns it as `commit_files` from `POST /solve`. The platform builds the
Dockerfile from this same content. Confirm that `/solve` returns exactly two
files with the expected names.

### Runtime contract

When the platform runs the image:

- It runs the container entry point (`python3 /app/bot_runner.py` in the example).
- `bot_runner.py` is platform-owned. It imports `bot.bot` and calls
  `run_bot(url)`. `bot.py` is therefore imported as `bot.bot`, which the example
  image provides by copying the bot folder to `/app/bot`.
- It reads the target URL from `CHALLENGE_WEB_URL` and the session id from
  `SESSION_ID` (used for logs only).
- Exit code `0` means `run_bot` returned `True`. Exit code `1` means it returned
  `False` or the URL is missing.
- The run must finish within the challenge bot timeout (default **120 seconds**).

The example runs WebKitGTK under Xvfb. The runner starts Xvfb on `:99` when no
`DISPLAY` is set, so a display server is provided by the bot itself.

## Scoring

The platform returns a score between `0.0` and `1.0` and a feedback string:

| Feedback | Meaning |
| --- | --- |
| `scored` | Scored; no problems reported. |
| `scored; failed: <area>, ...` | Scored; the listed areas were reported as failing. |
| `hard_fail=<reason>` | Rejected; score `0.0`. |

Feedback is intentionally brief. It does not include thresholds, check
details, or the rules behind each area.

Hard-fail reason codes:

| Code | Meaning |
| --- | --- |
| `payload` | The payload or session binding is invalid, incomplete, duplicated or expired. Also used for a wrong or incomplete task. |
| `integrity` | The data collector was tampered with. |
| `automation` | Definitive automation markers were found. |
| `realm_mismatch` | Browser contexts of the same page contradict each other. |
| `untrusted_input` | Task input was generated by a script, not by a user. |

Full feedback reference: [scoring feedback](../../../src/challenges/bot_virus/docs/feedback.md).

## Validation feedback

Validation runs before scoring. A passing check returns exactly:

`Script is legitimate and follows the challenge rules.`

Any other failure returns one fixed title. Titles never name the file, the
check, or the technique involved.

| Outcome | Validation reason |
| --- | --- |
| Package installs from a language package manager, or any direct fetch | `Prohibited package installs are used.` |
| Wrong file set or structure | `Submission has an invalid file structure.` |
| Required page actions missing or incomplete | `Required browser actions are missing or incomplete.` |
| Unsafe or unclear code | `Submission contains unsafe or unclear code.` |
| Unauthorized network resource | `Submission contacts unauthorized resources.` |
| Security rule violation (sandbox, privileges, host config, page or API spoofing) | `Submission violates the challenge security rules.` |
| Runtime criteria (waits, error handling, cleanup) | `Submission does not meet the required runtime criteria.` |
| Base image not allowed | `Base image is not allowed.` |
| OS package policy violated | `System package policy is violated.` |
| Hidden or indirect build source | `Build sources are not allowed.` |
| Entry point does not start the bot | `Container entrypoint is invalid.` |

If several rules fail, the title for the earliest failing group is returned.
Titles are not combined or expanded.

## Miner-side checks

Miners do not call the challenge API. Before publishing, verify each item with
the miner commit example and the [testing manual](testing_manuals.md):

- Practice page: every requirement shows PASS.
- Ruff: `bot.py` has no findings.
- Line limits: `bot.py` at most 2,000 lines, `Dockerfile` at most 500.
- Structure: `src/commit/` holds exactly `bot.py` and `Dockerfile`.
- Bot: defines `run_bot(url: str) -> bool`, uses only the assigned URL, has a
  bounded timeout on every wait, and closes browser and driver on every path.
- Dockerfile: `FROM` is an allowed base; `apt` is the only package manager;
  no `curl`, `wget`, `git`, `ADD` remote, `COPY --from`, or multi-stage build;
  `CMD` or `ENTRYPOINT` starts `bot_runner.py` or `bot.py`.
- Image: builds for `linux/amd64` with allowed sources only.

The [miner commit example](https://github.com/RedTeamSubnet/bot-virus-challenge/tree/main/examples/miner_commit)
is a starting point. Check whatever you submit against the contract on this page.
