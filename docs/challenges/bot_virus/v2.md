# Bot Virus v2

## Objective

Build a containerized browser bot that completes the challenge web page
without being flagged by the bot checks. The score comes from the platform's
evaluation of your submitted image.

## What changed from v1

- v1 submissions are not compatible with v2. Do not reuse them.
- The v1 rule that allowed OS packages only no longer applies. Package sources
  for v2 are listed in [Dockerfile sources](#dockerfile-sources).

## Evaluation flow

1. Write `src/commit/bot.py` and `src/commit/Dockerfile` (see
   [Submission contract](#submission-contract)).
2. Verify locally with the miner commit example (see the
   [testing manual](testing_manuals.md)).
3. Build and publish the image, then submit it following the
   [build and publish workflow](../../miner/workflow/3.build-and-publish.md).
4. The platform evaluates your image and reports a score between `0.0` and
   `1.0`, with feedback.

A failed build, a failed run, or a missing result scores `0.0`.

The evaluation infrastructure is private. Miners cannot run it locally.

## Submission contract

`src/commit/` must contain exactly two files:

| File | Requirement |
| --- | --- |
| `bot.py` | At most **2,000** lines. Must pass Ruff. Must define `run_bot(url: str) -> bool`. |
| `Dockerfile` | At most **500** lines. Defines the image the platform builds. |

Use these exact names. Missing, renamed, duplicated, or extra files are rejected.

### Entry point

`run_bot(url: str) -> bool` receives the challenge page URL, performs the
required page actions, and returns `True` on success or `False` on failure.
Close every browser or driver you open, including on failure.

### Required page actions

The page actions and element ids that the bot must use are defined by the
practice page in the miner commit example
(`examples/miner_commit/practice/index.html`). Run the practice page to confirm
your bot meets every requirement; each one shows PASS or FAIL.

### Ruff

`bot.py` must pass Ruff with the example's `.ruff.toml`:

```sh
ruff check --config .ruff.toml bot.py
```

### Dockerfile sources

Fetch content only from these providers. Any other source fails the build.

| Category | Allowed provider |
| --- | --- |
| Base image (`FROM`) | Base images the challenge makes available |
| Debian packages (`apt-get`) | Debian package repositories |
| Ubuntu packages (`apt-get`) | Ubuntu package repositories |
| Alpine packages (`apk`) | Alpine Linux package CDN |
| Python packages (`pip`) | PyPI and Python Package Index file host |
| JavaScript packages (`npm`, `yarn`) | npm registry and Yarn registry |
| Java packages (Maven) | Maven Central |
| Go modules (`go`) | Go module proxy and Go checksum database |
| Rust crates (`cargo`) | crates.io |

Build for `linux/amd64`:

```sh
DOCKER_BUILDKIT=1 docker build --platform linux/amd64 -t <image>:<tag> .
```

## Scoring

The platform returns a score between `0.0` and `1.0` and a feedback string:

| Feedback | Meaning |
| --- | --- |
| `scored` | Scored; no problems reported. |
| `scored; failed: <area>, ...` | Scored; the listed areas were reported as failing. |
| `hard_fail=<reason>` | Rejected; score `0.0`. |

Feedback is intentionally brief. It does not include thresholds, check
details, or the rules behind each area.

## Miner-side checks

Miners do not call the challenge API. Before publishing, verify each item with
the miner commit example and the [testing manual](testing_manuals.md):

- Practice page: every requirement shows PASS.
- Ruff: `bot.py` has no findings.
- Line limits: `bot.py` at most 2,000 lines, `Dockerfile` at most 500.
- Structure: `src/commit/` holds exactly `bot.py` and `Dockerfile`.
- Image: builds for `linux/amd64` with allowed sources only.

The [miner commit example](https://github.com/RedTeamSubnet/bot-virus-challenge/tree/main/examples/miner_commit)
is a starting point. Check whatever you submit against the contract on this page.
